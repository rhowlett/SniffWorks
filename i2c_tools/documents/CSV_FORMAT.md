# Capture CSV format (v2)

The interchange format between the sniffers, the replay tool, and any
external producer (firmware logs, scripts). Written by
`TransactionLogModel.export_csv` (`core/log_model.py [XREF: csv-format]`),
read by `ui/common/capture.py`. This document is normative; the validator
`tools/validate_capture_csv.py` enforces it.

## File

- UTF-8 (the PEC column uses ✓ / ✗), CRLF or LF line endings.
- First row is the exact header:

```
Time,#,Addr,Dir,Len,Data (hex),Int,ASCII,Decode,NAK,Start,Stop,PEC,SCL (Hz)
```

  A **v1** file has the same header without the trailing `,SCL (Hz)`;
  readers must accept both (see Versioning).

- One row per bus transaction (one addressed transfer). A register read
  performed as write-pointer + read is TWO rows; the stream decoder
  re-pairs them on load (including across an intervening STOP).

## Columns

Canonical columns are authoritative on load; informational columns are
regenerated by the tools and may be left empty by external producers.

| Column | Kind | Format | Semantics |
|---|---|---|---|
| Time | canonical | `HH:MM:SS.mmm` | Wall-clock, millisecond resolution. Used for display and replay ordering; rows are consumed in file order regardless. |
| # | informational | integer ≥ 1 | Export sequence number. Ignored on load. |
| Addr | canonical | `0xNN` | **7-bit** address, hex. Always 7-bit in the file — the 8-bit display toggle never affects export. Loader accepts with or without `0x`. |
| Dir | canonical | `W` \| `R` | Transfer direction. |
| Len | informational | integer ≥ 0 | Byte count of Data. Regenerated on load. |
| Data (hex) | canonical | `AA BB CC` | Uppercase hex pairs, space-separated (loader also tolerates commas). Empty for zero-length transfers (address-only probes). |
| Int | informational | decimal | **Big-endian** unsigned integer of the data bytes (canonical BE regardless of device byte order or display overrides). Empty when Data is empty. |
| ASCII | informational | text | Printable bytes, `.` elsewhere. Regenerated. |
| Decode | informational | text | Decoder output at export time (respects active filters/decoders). Regenerated on load against the loaded decoders; never parsed. |
| NAK | canonical | `NAK` \| empty | Address or data byte not acknowledged. |
| Start | canonical | `S` \| `Sr` \| empty | Start condition: normal start, repeated start. Loader is case-insensitive. |
| Stop | canonical | `P` \| empty | Stop condition terminated the transfer. |
| PEC | canonical | `✓ PEC` \| `✗ PEC` \| empty | SMBus PEC check result at capture time (empty = not checked). Restored on load for CRC coloring; the loader does not recompute it. |
| SCL (Hz) | canonical (v2) | integer 1–10 000 000 \| empty | SCL frequency of this phase **as measured by the capture probe** (ion probe fw ≥ 1.3, bit-bang mode — see `embedded/docs/PROTOCOL.md` §1.1.1). Empty = not measured (AD2 sniffers, slave-monitor/master firmware, older firmware, external producers). Restored on load; the table shows it in kHz. |

## Semantics that trip people up

- **Addr is 7-bit.** `0x08` in the file may appear as `0x10`/`0x11` in an
  8-bit-mode logic analyzer; convert before comparing.
- **Int is big-endian by convention** even for little-endian devices: it is
  a stable human-readable canonical form, not the device interpretation.
  Decoders apply their own byte order to Data.
- **Pointer/read pairing is positional.** The loader replays rows through
  the stream decoder in order; a `W [reg]` row (with or without `P`)
  arms the register for the next `R` row at the same address.
- **Zero-length rows are meaningful.** Address-only probes (bus scans)
  export with `Len=0`, empty Data/Int, and typically `NAK`.
- Filters at export time select WHICH rows are written, never the format.

## Minimal external producer

External tools may emit only the canonical columns (header must still be
complete; informational cells may be empty):

```
Time,#,Addr,Dir,Len,Data (hex),Int,ASCII,Decode,NAK,Start,Stop,PEC,SCL (Hz)
19:52:47.479,,0x6B,W,,2E,,,,,S,,,
19:52:47.479,,0x6B,R,,40 00,,,,,Sr,P,,
```

(A v1 producer may still omit the `SCL (Hz)` column entirely.)

## Versioning

The header row is the version signature (no version cell in the file):

| Version | Header | Since |
|---|---|---|
| v1 | `Time … PEC` (13 columns) | 2026-07 |
| v2 | v1 + trailing `SCL (Hz)` (14 columns) | 2026-09-30, project 1.4.0 |

Current tools write v2 and read both. New columns are only ever appended
at the end, and every addition bumps this document and keeps the loader
and `tools/validate_capture_csv.py` backward-compatible with older files.

Note: this versioning is the header-signature scheme described here. The
planned `schema/capture.schema.json` with an explicit version line (review
item M1, program Phase 6) will supersede it.
