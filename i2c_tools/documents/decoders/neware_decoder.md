# Smart Battery (SBDS v1.1) via Neware BTS — I2C decoder

Smart Battery Data Specification v1.1 command set as polled by a Neware BTS cycler (SMBus host). Address 0x10 (7-bit) taken from working_test_1.csv; SBDS standard is 0x0B — regenerate with --address if the pack moves. Sources: Neware-supplied register file `documents/decoders/Smart Battery Registers.txt` [Neware], the user's Neware summary [user], SBDS v1.1 [SBDS]. The Neware file's default address is 0x0B; this capture's channel uses 0x10. Assumes CAPACITY_MODE = 0 (mAh/mA) and SpecificationInfo VScale = IPScale = 0; if either differs, capacity/current/voltage units are wrong. Words are little-endian (SMBus 3.3 §6.5.4-6.5.5). Writable: 0x00-0x04, plus 0x14/0x15 per the Neware file. Block reads 0x20-0x23 decode the length; text is in the ASCII column. Not decoded: 0x1D-0x1F (reserved), 0x2F/0x30-0x3B/0x40-0x4F manufacturer extensions, battery-to-charger broadcasts and AlarmWarning (Host Notify). Generated by build_neware_decoder.py.

- **Address:** 0x10 (8-bit W 0x20 / R 0x21)
- **File byte order:** le
- **Schema version:** 4  ·  **Rules:** 44
- **Note:** SMBus words: Data Byte Low first.

## Provenance

Each rule description carries a tag. **[Neware]** means the Neware-supplied `documents/decoders/Smart Battery Registers.txt`, which covers names, sizes, access, units, BatteryStatus bits and error codes. **[user]** means the earlier Neware summary. **[SBDS]** means Smart Battery Data Specification v1.1. `test_neware_doc_conformance.py` parses the Neware file and checks every register against this decoder.

## Assumptions and open items

- **Address 0x10** is what `working_test_1.csv` shows. The Neware file's default is 0x0B (SBDS standard), so the capture's channel was configured to a non-default address. For a 0x0B pack, use `i2c_decoders/smbus1v1_decoder.json` instead of regenerating this file at 0x0B, which would collide with it.
- **Units follow the Neware file**, which fixes BatteryMode CAPACITY_MODE = 0 (mA, mAh). If a pack sets CAPACITY_MODE = 1, rules 0x01, 0x04, 0x0F, 0x10 and 0x18 are in 10 mW / 10 mWh. SpecificationInfo VScale = IPScale = 0 is assumed.
- **0x14 / 0x15 write rules** exist because the Neware file lists them RW. SBDS defines them read-only at the battery; the write form targets the Charger (0x09).
- **Cell voltages 0x3C–0x3F** follow the Neware file (0x3C = Cell4 … 0x3F = Cell1, read only). SBDS 1.1 defines these codes only as OptionalMfgFunction4..1; the order matches TI bq40z, and Microchip PS401 uses the reverse.
- **Block reads 0x20–0x23** decode the length; the text is in the capture's ASCII column. DeviceChemistry text decodes when its length is at least 4.
- **65535** in the time and charge-request registers means N/A or maximum; it is shown as the number.
- **Not decoded:** 0x1D–0x1F (reserved), OptionalMfgFunction5 (0x2F), ManufacturerAccess subcommand responses, battery-to-charger broadcasts, AlarmWarning (see `i2c_decoders/smbus1v1_decoder.json`).

## Differences from SBDS in the Neware material

| Item | Neware says | SBDS says | Decoder follows |
|---|---|---|---|
| 0x14 / 0x15 access | RW | Read at the battery (App A); written by the battery to the Charger | Both: read rule plus Neware write rule |
| 0x3C–0x3F | CellVoltage4..1, RO | OptionalMfgFunction4..1, r/w, manufacturer defined | Neware |
| ReservedCommand (0x2) | "command reserved for manufacturer use" | Code reserved by this version of the specification (App C) | Name only; no semantics encoded |
| AccessDenied (0x4) | "not permitted in the battery's current state" | Write to a read-only function code (App C). The state-based meaning is a vendor extension, e.g. TI sealed mode | Name only |
| Earlier summary: BatteryStatus | Omitted bit 8 and the error code | Bit 8 REMAINING_TIME_ALARM; [3:0] error code | SBDS, now confirmed by the Neware file |
| Earlier summary: bq27421 | Grouped with SBS gauges | Not an SBS command-set gauge | n/a |
