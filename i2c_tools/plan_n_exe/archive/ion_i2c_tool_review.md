# ion_i2c_tool — Code Review

**Package:** `ion_i2c_tool.zip` (378 files, `PROJECT_VERSION = 1.2.0`)
**Reviewed:** 2026-09-25
**Scope:** completeness against the product description, bugs, consistency, extensibility.
No code was changed. Every item below is a proposal, not an applied edit.

**Description reviewed against:** software for sniffing an I2C bus with a purpose-built
I2C hand tool, an AD2, or a Nucleo POC; reads a JSON decoder file per device to produce
human-readable data flow; customizable dashboard (register monitor); decoder editor;
schemas for both the input/output CSV and the decoder file.

## How to read this

* **Sev**: H = wrong output or data loss · M = functional defect or friction · L = hygiene.
* **(verified)** = reproduced by running the shipped code against the shipped decoders.
  Everything else comes from reading the source.
* Each row states the issue, the recommended fix, and the files the fix touches.

## 2. Bugs

### 2.1 Decoder file, schema, and editor

| # | Sev | Issue | Recommended fix | Files |
|---|---|---|---|---|
| B1 | H | **(verified)** Every conditional in the decoder schema uses `if: { properties: … }` without `required`, so the condition passes vacuously when the key is absent. A perfectly valid rule that omits `format` (defaulting to `dec`) is reported as **"'bit_fields' is a required property"**. The subcommand, register, and general-call conditionals have the same defect. | Add `"required": [...]` naming the tested property inside each `if` (7 `allOf` branches). | `schema/decoder.schema.json` |
| B2 | H | **(verified)** `DecodeSchema.to_json()` drops all top-level metadata: `device`, `description`, `i2c_address`, `i2c_address_hex`, `i2c_address_8bit`, `byte_order_note`. Any save from the editor strips them from all three shipped decoders. Downstream, `DecoderSetManager` falls back to the filename, so the UI list and the Registers tab titles degrade from "BQ76905" to "bq76905_decoder". | Store the parsed document's non-rule keys on the schema object (`self.metadata`) in `from_json` and re-emit them in `to_json`, preserving unknown keys. | `core/decode_schema.py` |
| B3 | M | **(verified)** A `format: "bits"` rule whose `bit_fields` list is empty loses the key on save, and the saved file then fails its own schema. Live example: bq76922 rule 12, "PF Alert D" (reg 0x10), whose description says "verify vs SLUUCG7 §12.2 (all reserved)". | Always emit `bit_fields` for `bits` rules (even empty), or require `minItems: 1` in the schema and populate the rule. Track the unverified register as an open decision item. | `core/decode_schema.py`, `schema/decoder.schema.json`, `i2c_decoders/bq76922_decoder.json` |
| B4 | H | **Editor "Add / Update Rule" rebuilds the rule from the form fields**, so every field the form does not carry is silently wiped: `description` (present on 164 of the 164 shipped rules across the three decoders), `fields`, `register_width_bytes`, `subcommand`/`subcommand_reg`, and bit-field `description`. Worse, `_collect_bit_fields` re-parses the display string and **drops any enum field whose names contain a comma** — **(verified)** 13 bit fields in `bq25731_decoder.json`. Errors from `_parse_bf_spec` are discarded, so the loss is silent. Changing address/register/direction adds a second rule instead of moving the first. | Keep the selected `DecodeRule` and apply form values with `dataclasses.replace`, so unedited fields survive. Store bit fields as objects on the row (`Qt.UserRole`) instead of round-tripping a comma string. Surface parse errors. Treat a key change as a move (remove old key, add new). | `ui/widgets/decode_editor.py` |
| B5 | H | **Clicking or removing a subcommand row in the editor silently does nothing.** `_on_row_clicked` and `_on_remove` rebuild the key from Dir + Register (`_ttype_from_dir` → `simple_write`, register `None`), which never matches a subcommand rule keyed `(address, code, "subcommand")`. | Store `rule.key()` in the row's `Qt.UserRole` when populating the table, and use it for both lookup and removal. | `ui/widgets/decode_editor.py` |
| B6 | L | **`subcommand_reg` default disagrees between schema and code.** The schema documents `default: 62` (0x3E); `StreamDecoder._subcommand_reg` returns `None` when no rule carries the field, which disables subcommand pairing entirely. | Pick one: either apply the 0x3E default in code or drop the default from the schema and require the field. | `core/decode_schema.py`, `schema/decoder.schema.json` |
| B7 | M | **The safe expression evaluator can hang or exhaust memory from a decoder file.** `**` and `<<` are unbounded (`X**X`, `1<<10**9`). `min`/`max`/`round` with wrong arity raise `TypeError`, which is not caught by the `DecodeError` handler in `_render` and escapes into the model. | Cap exponents and shift counts, and convert `TypeError`/`ValueError`/`OverflowError` into `DecodeError` at the evaluator boundary. | `core/decode_schema.py` |

### 2.2 Decode stream and protocol

| # | Sev | Issue | Recommended fix | Files |
|---|---|---|---|---|
| B8 | M | **The single-byte simple-write branch is unreachable dead code.** `_is_pointer_write` returns `True` for any 1-byte write, so the `if len(data) == 1` branch below it never runs: `simple_write` rules for single-byte writes never decode, and the byte is instead stashed as a pending register that mis-pairs the next read. | When the address has a `simple_write` rule and no indexed rule matching that byte, decode it as a simple write. Otherwise treat it as a pointer. | `core/decode_schema.py` |
| B9 | H | **SMBus PEC is computed over the wrong bytes for combined transactions.** The spec covers Addr+W, command, repeated-start Addr+R, and data; the code computes over the current phase only (read address + data). Every SMBus read-word/read-block therefore shows ✗ PEC. Three separate implementations share the flaw. | Compute PEC where the phases are paired (the stream/decode layer), not per phase, and mark it "not checkable" when the write phase was not captured. | `core/i2c_controller.py` (`read`, `write_read`, `spy_poll`), `core/ion_backend.py`, `core/log_model.py` |
| B10 | H | **AD2 `spy_poll` discards continuation segments.** When `fStart == 0` it returns "no data" and drops the buffer, so any transaction split across status calls is truncated — exactly what happens to the 36-byte subcommand block reads this tool is built to decode. Stop-only status is lost the same way. | Accumulate segments per address phase until Stop or Restart (the Digilent `Digital_I2c_Spy.py` pattern), then emit one transaction. | `core/i2c_controller.py`, `core/spy_worker.py` |
| B11 | M | **The IonWorker stop-drain exits immediately.** `while time.monotonic() < deadline and link.pump():` — with `timeout=0` the first quiet read returns 0 and ends the loop, so the final frames never reach the log. | Loop to the deadline with a short sleep, breaking only on a real port error. | `core/ion_backend.py` |
| B12 | M | **`IonMasterLink` desyncs after a link timeout.** A late TXN frame stays in `_pending` and is returned as the answer to the *next* command, so a replay compare can silently compare the wrong pair. | Flush `_pending` and the frame parser before each send; longer term, add a sequence tag to the master command/response frames (protocol v2). | `core/ion_master.py`, `core/ion_protocol.py`, `embedded/.../frame_protocol.h`, `PROTOCOL.md` |
| B13 | M | **The master's NAK on the final read byte — normal I2C — is rendered as an error** (red row, error colouring, counted as a NAK). Note that the search's frame grouping in `_compute_visible` deliberately relies on those NAKs as frame delimiters, so the two must change together. | Distinguish address NAK, data NAK, and expected end-of-read NAK (the firmware already knows which); colour only the first two, and base frame grouping on Stop/Start instead. | `core/log_model.py`, `core/i2c_controller.py`, `core/ion_backend.py`, firmware flags |

### 2.4 Dashboard (Registers view)

| # | Sev | Issue | Recommended fix | Files |
|---|---|---|---|---|
| B18 | M | **The value cache is keyed by `rule.key()`, which includes the transaction type.** A write to an R/W register never updates the register's row, because that row belongs to the `indexed_read` rule (bq25731 ships 17 `indexed_write` rules). The dashboard therefore shows a stale value after the host changes a setting. | Key the cache by `(address, register)` and let both read and write rules feed it, or explicitly pair read/write rules for the same register. | `ui/widgets/registers_view.py`, `core/decode_schema.py` |
| B19 | M | **Register tabs are built from the merged schema filtered by `min(entry.addresses)`.** When two decoders share an address — bq76905 and bq76922 are both 0x08 — each device tab shows the other's rules, and whichever loaded last wins the merge. `display_groups` are unioned by name globally, so same-named groups from different devices collapse. | Build each view from that entry's own schema; namespace display groups per device/address; warn on address collision in the Decoders list. | `ui/widgets/registers_tabs_host.py`, `core/decoder_manager.py`, `ui/widgets/registers_view.py` |
| B20 | M | **The bit matrix only renders one or two bytes.** `data_bytes >= 2` yields exactly a high/low row pair, so bits 16 and above of a 3- or 4-byte bit register are not displayed at all. | Generate one row per byte for N bytes, labelled by byte index. | `ui/widgets/registers_view.py` |
| B21 | M | **Numeric formatting differs from the log and breaks at 5 digits.** The dashboard uses `f"{value:.4g}"`, so a non-integer ≥ 10,000 renders as `1.235e+04`; the log uses `.4f` stripped. | Extract one shared `format_value(value, fmt, width)` helper and use it in both. | `ui/widgets/registers_view.py`, `core/decode_schema.py` |
| B22 | L | **Bit cell labels prefer the enum value name over the field name.** `_bit_name` takes `names[-1].split("=")[0]`, so a flag with names `["Disabled","Enabled"]` is labelled "Enabled" regardless of state, while `BitField.name` is ignored. "Reserved" detection then keys off that rendered label (`startswith("RSVD")`). | Prefer `bf.name`, fall back to the enum name; mark reserved from the field definition, not the label text. | `ui/widgets/registers_view.py` |
| B23 | L | **Multi-bit field colouring uses the field value as a 24-bit RGB colour.** Small values (1, 2, 3) are near-black, get complemented to near-white, and are visually indistinguishable — and the legend only advertises green/red/grey. | Use a small qualitative palette indexed by value, or a single "non-zero" colour with the value in the cell text; update the legend to match. | `ui/widgets/registers_view.py` |

## 4. Refactoring for extensibility

| # | Issue | Recommended fix | Files |
|---|---|---|---|
| R1 | **The two sniffer windows duplicate roughly 60% of their logic** — decoder wiring, capture stats, cross-thread transaction relay, PEC toggling, theme apply, close guard — with small divergences that are already bugs (B24, B26, C10). Adding the hand tool as a third backend means a third copy. | Define a `CaptureBackend` interface (`start/stop/set_check_pec` plus `transaction_captured/error/stats/status` signals) with `AD2SpyBackend`, `IonBackend`, and later `HandToolBackend`, and fold the shared UI into one `BaseSnifferWindow` parameterized by backend and device panel. | new `core/backends/`, `ui/sniffer_window.py`, `ui/sniffer_ion_window.py`, `core/spy_worker.py`, `core/ion_backend.py` |
| R2 | **The universal transaction model lives in the AD2-specific module.** `I2CTransaction`, `I2CDirection`, and `smbus_crc8` sit in `core/i2c_controller.py`, which imports ctypes and the DWF API, so every backend and the CSV loader drag in AD2 specifics. `ion_master` then monkey-patches `timeout` and `result` onto the dataclass. | Move the model to `core/transaction.py` with proper optional fields (`timeout`, `result`, `overflow`, `device_t_us`). | `core/i2c_controller.py`, `core/ion_backend.py`, `core/ion_master.py`, `core/log_model.py`, `ui/common/capture.py`, `tests/` |
| R3 | **Layering violations against the stated architecture** ("core: no UI imports"): `core/log_model.py` imports `ui.theme` inside `data()`; capture parsing (pure data logic) lives in `ui/common/capture.py`; `decode_capture` and `load_transactions` parse the same CSV rows twice with subtly different rules. | Move capture I/O to `core/capture_io.py` with a single row parser producing transactions; decode by feeding those transactions. | R4 | **A device-specific protocol is hard-coded in the generic decode engine**: the 0x3E echo, the 36-byte `[echo][32-byte buffer][checksum][length]` frame, the TI checksum formula, and the `sub_reg + 2` transfer-buffer offset are all baked into `decode_schema.py`. Supporting a non-TI subcommand device requires editing the engine. | Describe it in the decoder JSON as a `subcommand_protocol` block (code register, code width/endianness, buffer offset, frame layout, checksum algorithm) and make the engine data-driven. | `core/decode_schema.py`, `schema/decoder.schema.json`, `i2c_decoders/*.json` |
| R5 | **The I2C address is baked into every rule**, so a bus with two identical ICs (or a strap-selected address) needs a duplicated, hand-edited decoder file. | Add a file-level default address plus a per-instance address override applied at load time in `DecoderSetManager`; show the instance address in the decoder list and tab titles. | `core/decoder_manager.py`, `core/decode_schema.py`, `schema/decoder.schema.json`, `ui/widgets/sidebar_sections.py` |
| R6 | **Observer and render options are mutable state on the shared schema**: `on_rule_decoded` is a single attribute (the last attacher wins — one dashboard cache only), and `multiline_bits` is a flag on a schema that may be shared between windows, so a replay window's formatting choice can leak into a sniffer's. | Replace the callback with a listener list or Qt signal; pass render options per call (or per view) instead of mutating the schema. | `core/decode_schema.py`, `ui/widgets/registers_view.py`, `core/log_model.py`, `ui/replay_window.py` |

The log grows without bound. | Cache the subcommand register per address; extend visibility incrementally under search; batch row appends and dashboard updates on a ~50 ms timer; offer an optional ring-buffer row cap. | `core/decode_schema.py`, `core/log_model.py`, `ui/log_panel.py`, both sniffer windows, `ui/widgets/registers_view.py` |

## 5. Suggested order of work

1. **Data-loss first** — B4, B5, B2, B3 (decoder editor and save path). Until these are fixed, using the editor on the shipped decoders destroys datasheet content.
2. **Correctness of the captured record** — B10, B9, B14/B15/B16 (truncated AD2 captures, wrong PEC, lossy CSV).
3. **The two schemas** — B1 (schema is currently wrong about valid files), then M1 and M2 so both formats are defined and enforced.
4. **Decide the scope questions** — M3 (gateway app), M9 (master mode/ALERT), M10 (Windows). Each is currently half-present in docs, tests, or dead code.
5. **Then refactor** — R1 and R2 before adding the hand tool backend (M4), R4/R5 before adding non-TI or multi-instance devices.
6. **Hygiene alongside** — C1–C12, and R9 so the next regression is caught by the suite.
